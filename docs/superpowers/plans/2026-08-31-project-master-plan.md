# NADBID 项目开发总计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 NADBID 便士拍卖 Web3 应用从前端 Demo 推进到商业化上线标准，包含完整的钱包连接、链上交易、数据层和测试部署。

**Architecture:** 前端 React 19 + TypeScript + Vite 6 + Tailwind CSS 4，状态管理 Zustand，路由 React Router 7；链上交互通过 wagmi/viem 接入 Monad 测试网智能合约；数据层采用合约事件监听 + 后端 API 混合架构。

**Tech Stack:** React 19, TypeScript 5.8, Vite 6, Tailwind CSS 4, Zustand 5, React Router 7, Motion 12, wagmi 2.x, viem 2.x, lucide-react

---

## 项目边界

### In Scope（做什么）
1. **前端 UI 完整化**：所有页面按照 demo 设计风格统一，包含 Arbitration、Wallet、Docs 页面
2. **钱包连接**：MetaMask / Phantom 等 EVM 钱包连接，Monad 测试网网络切换
3. **核心交易功能**：拍卖出价、PASS Mint/Burn、Stake/Unstake、Claim Rewards、仲裁投票
4. **数据层升级**：从 mock 数据切换到智能合约真实数据，事件监听，实时更新
5. **交易状态管理**：Pending → Confirmed → Failed 完整状态追踪，错误处理和重试
6. **测试**：组件单元测试，关键流程 E2E 测试
7. **部署准备**：生产环境构建优化，环境变量配置，Vercel 部署

### Out of Scope（不做什么）
1. **智能合约开发**：假设合约已部署到 Monad 测试网，只做前端集成
2. **后端 API 开发**：假设后端 API 已存在，只做前端调用
3. **移动端原生应用**：只做响应式 Web 应用
4. **多链支持**：MVP 阶段只支持 Monad 测试网
5. **法币出入金**：只支持链上加密货币
6. **复杂的数据分析仪表盘**：MVP 阶段只做基础数据展示

## 风险和依赖

### 关键依赖
1. **智能合约已部署**：Monad 测试网合约地址和 ABI 必须提供
2. **后端 API 可用**：Points 系统、推荐系统、KOL 数据等需要后端 API
3. **Monad 测试网稳定**：测试网 RPC 节点稳定可用
4. **钱包兼容性**：MetaMask 等主流钱包支持 Monad 链

### 主要风险
1. **合约接口变更**：智能合约接口可能在开发过程中变更，需要前端同步调整
2. **测试网不稳定**：Monad 测试网可能不稳定，影响开发和测试
3. **Gas 费估算不准确**：新链的 Gas 费估算可能不准确，需要调整
4. **性能问题**：链上数据查询可能较慢，需要优化缓存和轮询策略

### 缓解措施
1. **合约接口冻结**：开发前冻结合约接口，变更需走变更流程
2. **多 RPC 节点配置**：配置多个 RPC 节点，自动故障转移
3. **Gas 费缓冲**：Gas 费估算增加 20% 缓冲
4. **数据缓存层**：实现前端数据缓存，减少链上查询次数
