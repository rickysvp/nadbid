# NADBID 链上拍卖协议 — MVP 技术规格 (Spec v0.1)

- 日期：2026-09-14
- 状态：已与产品方确认，进入实现规划
- 链：Monad（测试网起步，架构预留跨链）
- 结算资产：USDC（稳定币）

---

## 1. 产品定位

> **稳定币结算的低价捡漏拍卖协议**：出价不退还、同区块随机保留、前序出价者分红补偿、最后有效出价者以极低价获得高价值链上资产。

核心叙事："10 USDC 起拍，可能几百 USDC 拿走 1 万 USDC 的资产"。

---

## 2. 核心规则（已拍板，不可变更）

| 编号 | 规则 | 参数/说明 |
|---|---|---|
| R1 | 出价不退还 | 被保留的有效出价全额进入资金池，不返还 |
| R2 | 资金池分配 | 85% 拍卖人 / 15% 奖励池（结算时各方收益扣 5% 平台费） |
| R3 | 平台手续费 | 出价时 1%（额外收）+ 结算时资金池 5%（各方收益扣 5%） |
| R4 | 增幅 | 默认 1%/笔；发起人可选档位 1% / 2% / 5%（参数化） |
| R5 | 起拍价 | 发起人设定（建议下限 5-10 USDC） |
| R6 | 倒计时 | 120 秒，每次有效出价提交即重置；无新有效出价则结束 |
| R7 | 同区块多人同价 | 随机保留一笔进入资金池，其余可领取退款（全额含手续费） |
| R8 | 赢家 | 最后有效价格批次中随机保留的候选者，免费获得资产 |
| R9 | 分红 | B 模式：全员持续分红（分红指数），拍卖中只记账、结束后统一结算 |
| R10 | 硬顶 | 100x 总收益封顶（安全阀；15% 奖励池下实际不触发） |
| R11 | 发起人 | 禁止参与自己的拍卖（链上检查 seller != bidder） |
| R12 | 保留价 | 发起人可设置；成交价 < 保留价 → 流拍，全额退款（含手续费） |
| R13 | 结算资产 | USDC（Monad 测试网用测试 USDC） |
| R14 | 拍卖标的 | 白名单链上代币（WBTC/WETH/MON 等）+ NFT（ERC-721 / ERC-1155） |
| R15 | 结算 | 任何人可在满足条件时调用 finalize，无需管理员 |

## 3. 经济模型

### 3.1 资金流

```
出价者支付 B × 1.01
  ├─ 0.01B → 平台（出价手续费，立即归集）
  └─ B → 资金池
              ┌─ 5% → 平台（结算费，各方收益扣 5%）
资金池结算 → ─┤
              ├─ 80.75% → 拍卖人（= 85% × 95%）
              └─ 14.25% → 奖励池（= 15% × 95%，按分红指数分给前序出价者）
赢家：免费获得资产（其最后一笔出价 B 已进池子，无额外付款）
```

### 3.2 价格序列

- 起拍价 P0（第一笔有效出价的价格 = P0）
- 第 k 笔有效出价价格：`P_k = P0 × (1+g)^(k-1)`，g = 增幅率
- 成交价 = 最后有效出价的价格
- 累计池子：`S_N = Σ_{k=1..N} P_k = P0 × ((1+g)^N − 1) / g`

### 3.3 关键结构性质（1% 增幅）

- 稳态下 **池子 ≈ 成交价 × 100**（一般化：池子 ≈ 成交价 ÷ g）
- 价格翻倍需 70 笔；10 倍需 231 笔；100 倍需 463 笔
- **短拍卖（< 250 笔）拍卖人亏损**——保留价 + 官方/白名单发拍是安全网（见 §9）

### 3.4 数据模型参考点（P0=10, g=1%, 资产价值 10,000 USDC）

| 结束笔数 | 成交价 | 池子 | 拍卖人到手(80.75%) | 奖励池(14.25%) | 平台(6%) |
|---|---:|---:|---:|---:|---:|
| 100 | 27 | 1,732 | 1,398 | 247 | 104 |
| 200 | 73 | 6,466 | 5,221 | 921 | 388 |
| 300 | 199 | 19,040 | 15,375 | 2,713 | 1,142 |
| 400 | 543 | 53,600 | 43,282 | 7,638 | 3,216 |
| 463 | 1,002 | 100,600 | 81,235 | 14,336 | 6,036 |

早期出价者回报（分红÷投入）：N=300 → 0.90x；N=400 → 1.20x；N=463 → 1.40x。
结论：分红是"失败补偿"而非暴利；核心参与动机 = 低价捡漏机会 + 低成本博彩。

## 4. 分红指数模型（数学定义）

### 4.1 记账（拍卖进行中，无转账）

- 池子：`S_k = S_{k-1} + P_k`
- 累计收益率：`rpu_k = rpu_{k-1} + (r × P_k) / S_{k-1}`，其中 `r = 14.25%`（奖励池比例）
  - 注：第 k 笔的分红贡献分给"第 k 笔之前"的持有人（`S_{k-1}` 为分母，不含自身）
- 出价者 i 的加入快照：`snapshot_i = rpu_i`（第 i 笔更新前的 rpu）

### 4.2 结算（拍卖结束后）

- 出价者 i 应得分红：`dividend_i = P_i × (rpu_N − snapshot_i)`
- 硬顶：`dividend_i = min(dividend_i, P_i × 100)`
- 守恒校验：`Σ dividend_i = r × S_N`（未触发硬顶时精确成立）

### 4.3 硬顶截断处理（MVP）

- 15% 奖励池下实际最大回报 ~1.4x，硬顶实际不触发
- MVP 实现：截断余额归风险储备（spec 注明；V2 再考虑"达到上限者退出分红池、剩余红利流向未满者"的重分配）

### 4.4 流拍

- 成交价 < 保留价 → CANCELLED：全部有效出价全额退款（含 1% 手续费），分红不结算，资产退回发起人

## 5. 拍卖生命周期（状态机）

```
CREATED ──资产托管成功+参数校验──> FUNDED ──起拍校验通过──> LIVE
LIVE ──120s 无新有效出价──> SETTLING ──统一结算──> SETTLED
LIVE ──成交价 < 保留价──> CANCELLED（全额退款）
```

### 状态语义

| 状态 | 语义 | 关键动作 |
|---|---|---|
| CREATED | 发起人创建，参数锁定 | 资产未托管，发起人可撤销 |
| FUNDED | 资产进入 Escrow 且校验通过 | 校验：余额/授权/白名单 |
| LIVE | 出价中 | 价格等级推进、批次形成、倒计时 |
| SETTLING | 结束确认 | 派生批次随机数、计算分配、资产转移 |
| SETTLED | 完成 | 各方可 claim（拍卖人收益 / 分红 / 赢家资产） |
| CANCELLED | 流拍/异常 | 全额退款、资产退回 |

## 6. 同区块随机保留机制

### 6.1 规则

- **单区块单价格等级**：同一区块内只接受当前下一价格等级的出价；不允许同区块跳价
- 候选批次：`(auctionId, blockNumber, price)` 内的全部出价
- 同地址同批次最多一个候选资格；重复出价自动计入该地址的退款余额
- 保留者：`selected = hash(randomSource, batchId) % candidateCount`
- 落选者：全额退款（含 1% 手续费），可即时 claim，不进入资金池/分红链

### 6.2 随机源（MVP）

- 批次随机源 = **下一价格等级首次出价所在区块的 blockhash**
- 若拍卖结束（无下一等级）：用**拍卖结束区块的 blockhash**
- 理由：矿工/区块生产者需付出算力代价才能影响 blockhash，MVP 可接受
- V2：高价值拍卖切换 Chainlink VRF / 原生可验证随机数

### 6.3 安全性质

- Gas price、nonce、交易顺序、到达时间均不决定保留结果（同批次内）
- 保留结果在下一批次推进时才确定 → 落选者资金锁定时间 ≈ 1 个区块

## 7. 智能合约架构

### 7.1 模块

| 模块 | 职责 |
|---|---|
| NADBIDFactory | 创建拍卖、参数校验、资产白名单、增幅档位 |
| AuctionEngine | 状态机、价格等级、批次、倒计时、出价入口 |
| Randomness | blockhash 派生随机保留（VRF 适配器留 V2） |
| RewardLedger | 分红指数记账、结算、claim |
| Escrow | 资产托管（ERC-20 / ERC-721 / ERC-1155 适配器） |
| Treasury | 平台手续费归集、多签、时间锁 |

### 7.2 数据结构（示意）

```solidity
enum AuctionStatus { CREATED, FUNDED, LIVE, SETTLING, SETTLED, CANCELLED }

struct Auction {
    AuctionStatus status;
    address seller;
    AssetType assetType;          // ERC20 / ERC721 / ERC1155
    address assetAddr;
    uint256 assetTokenId;         // NFT 用
    uint256 assetAmount;          // ERC20/1155 用
    address bidToken;             // USDC
    uint256 startPrice;
    uint256 incrementPct;         // 1% = 100 (BPS)
    uint256 reservePrice;         // 0 = 无保留价
    uint256 lastPrice;            // 当前有效价格
    uint256 lastBatchBlock;       // 最后批次区块
    uint256 deadline;             // 最后有效出价 + 120s
    uint256 totalPool;            // 资金池累计
    uint256 rpu;                  // 分红指数
    uint256 batchCount;           // 已形成批次
    bool finalized;
}

struct BidBatch {                // 同区块同价候选批次
    uint256 auctionId;
    uint256 blockNumber;
    uint256 price;
    uint256 candidateCount;
    uint256 selectedIndex;       // 结算时写入
    bool randomResolved;
    bool refundsReady;           // 落选者可 claim
}

struct BidderState {             // 按 (auctionId, bidder) 记录
    uint256 pendingRefund;       // 落选/流拍待退款（含手续费）
    uint256 units;               // 被保留出价累计（分红份额基础）
    uint256 snapshotRpu;         // 加入时收益率快照
    bool rewardClaimed;
}
```

### 7.3 核心接口

```solidity
// Factory
function createAuction(
    AssetType assetType, address assetAddr, uint256 tokenId, uint256 amount,
    address bidToken, uint256 startPrice, uint256 incrementPct,
    uint256 reservePrice, uint256 duration
) external returns (uint256 auctionId);

// Engine
function placeBid(uint256 auctionId, uint256 price) external payable;
    // price 必须等于当前下一价格等级；同区块只接受同一价格
    // 重复出价（同地址同批次）→ 自动记退款
function finalize(uint256 auctionId) external;          // 任何人可调用
function claimRefund(uint256 auctionId, uint256 batchId) external;
function claimReward(uint256 auctionId) external;
function claimSeller(uint256 auctionId) external;
```

### 7.4 出价时序（placeBid 内）

```
1. 校验状态 == LIVE、price == 当前下一价格等级
2. 校验 msg.sender != seller
3. 校验本区块未推进过价格等级（batchBlock != block.number 或同级已存在）
4. 收取 B×1.01（1% 归平台，B 进合约）
5. 同地址同批次已有候选？→ 记退款余额，return
6. 加入候选批次；重置 deadline = block.timestamp + 120s
7. 若该区块为首个新价格等级 → 上一批次随机结果 = f(blockhash, batchId)
   落选者可立即 claimRefund
```

### 7.5 结算时序（finalize 内，CEI 顺序）

```
1. 校验状态 == LIVE 且 deadline 已过（120s 无新有效出价）
2. 状态 → SETTLING
3. 未解批次：随机源 = 结束区块 blockhash，解出全部批次保留者
4. 计算：总池 S、rpu_final、各方收益
5. 资产转移（Escrow → 赢家；流拍 → 卖家）
6. 平台费归集（Treasury）
7. 状态 → SETTLED
8. 拍卖人收益 / 分红：记录为可 claim（PullPayment，不循环转账）
```

## 8. 安全设计

| 风险 | 对策 |
|---|---|
| 重入 | ReentrancyGuard + CEI + PullPayment（不循环转账） |
| 同区块跳价 | 单区块单价格等级强制 |
| 零成本拖延 | 出价即重置倒计时；若为唯一候选则必被保留（成本真实）；单场批次上限兜底 |
| 女巫刷候选 | 同地址同批次单候选；单场最大候选地址数；共同资金来源监控（链下） |
| 区块生产者参与 | 同批次排序不影响结果；高价值拍卖 VRF（V2） |
| 发起人自竞拍 | 链上 seller != bidder 硬校验 |
| 资产风险 | 白名单校验（转账税/rebasing/可暂停/黑名单/隐藏铸币）；ERC-721/1155 数量校验 |
| 结算 DoS | finalize 任何人可调用 + 小额执行奖励；结算不遍历地址数组 |
| 随机数操控 | blockhash 需算力代价（MVP）；VRF（V2） |

## 9. 冷启动与运营策略

- **官方/白名单发拍**：MVP 阶段平台自持资产开拍（短拍卖亏损视为获客成本）
- 传播叙事："10 USDC 起拍 1 万 USDC 资产"
- 早期出价者 0.9-1.4x 分红补偿 + 捡漏预期 = 参与动机
- 市场跑热（拍卖持续 400+ 笔）后开放第三方卖家 + 提高拍卖人收益档位
- 保留价机制：卖家自控风险（设高易流拍白忙，设低易被捡漏）

## 11. 测试与验收标准

### 守恒不变式（任何场景必须成立）

```
Σ 有效出价 × 1.01 = 拍卖人收益 + 奖励池(含截断余额) + 平台(1%+5%) + 退款总额 + 储备
```

### 验收清单

- [ ] 资产必须先进入 Escrow 才能开拍；参数锁定不可改
- [ ] 单区块单价格等级；同地址同批次单候选
- [ ] 同区块同价只有一笔保留，其余可全额退款（含手续费）
- [ ] 保留结果与交易顺序/Gas/nonce 无关
- [ ] 分红守恒：Σ dividend = 14.25% × 池子（未触发硬顶）
- [ ] 100x 硬顶正确截断；截断余额入储备
- [ ] 保留价未达 → 流拍全额退款 + 资产退回
- [ ] 发起人无法参与自己拍卖
- [ ] finalize 无需管理员；不遍历地址数组
- [ ] 资产只转移给赢家；发起人无法提前取走
- [ ] 重入攻击测试通过（含恶意 token fallback）
- [ ] 女巫/机器人场景：批次上限、单地址单候选生效
- [ ] 前端与合约状态一致（LIVE/SETTLING/SETTLED/CANCELLED 全展示）

### 测试场景（阶段 0 模拟 + 合约测试）

- 5 / 20 / 100 用户；50% 机器人；单大户 40% 出价
- 同区块 2 / 10 / 100 候选
- 连续 10 场无新增用户；最后 30 秒 Gas 上升
- 流拍、硬顶触发、退款并发、结算重入

## 13. 未决项（实现前需确认）

1. **软结束/硬上限参数**：建议单场最多 500 个价格批次、最长 12 小时（防无限延长）——待定数值
2. **落选退款与流拍退款均含 1% 手续费**：已按"全退"实现，若改口径需同步前端
3. **监管**：全付 + 随机保留具博彩特征——地区限制 + 白名单 + 条款披露（产品/法务侧）
4. **跨链（V2）**：资产跨链 + 多链 USDC 结算，预留 Factory/适配器抽象
5. **VRF（V2）**：高价值拍卖随机源升级
6. **$NAD（V3+）**：代币经济（质押、折扣、NAD Mode）独立 spec
